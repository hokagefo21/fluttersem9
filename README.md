# Лабораторная работа №7

Flutter-приложение с регистрацией, Firebase Realtime Database и настоящими push-уведомлениями Firebase Cloud Messaging.

## Что настроено

- Firebase-проект: `lab7-uib`.
- Android-приложение: `com.example.untitled`.
- Realtime Database: `https://lab7-uib-default-rtdb.firebaseio.com`.
- Firebase Authentication: Email/Password.
- Разрешение уведомлений Android 13+, канал `registration`, обработка входящих сообщений и нажатия на уведомление.
- Отображение push в открытом приложении через flutter_local_notifications; в фоне уведомление показывает Android.
- Пароль передаётся только в Firebase Authentication. В Realtime Database паролей нет.
- Пользователь читает и записывает только собственный профиль; статус отправки push записывает только сервер.

## Как запустить

1. Дважды откройте `start-push-server.cmd` и оставьте окно открытым.
2. В Android Studio выберите эмулятор с Google Play Services и запустите `lib/main.dart`.
3. Разрешите уведомления, заполните имя, email, телефон и пароль от 8 символов.
4. После подтверждения записи в базу появится сообщение об успешной регистрации.
5. Сервер отправит push на FCM-токен этого устройства.
6. Для следующего аккаунта нажмите «Новая регистрация». После ошибки записи можно повторить сохранение без создания дубликата аккаунта.

Сейчас используется бесплатный план Spark. Сервер отправки работает на компьютере и отслеживает изменения в облачной базе. **Без работающего сервера новые push не отправляются**, но регистрация и сохранение данных продолжают работать. Приложению и компьютеру нужен интернет.

Сервер использует существующий вход Firebase CLI, не копируя секреты в проект. Если вход истёк, выполните `npx firebase-tools@latest login`, затем запустите сервер заново. Вторая копия сервера блокируется локальным портом 17877.

## Как это работает

Форма создаёт аккаунт Firebase Auth, получает UID и записывает профиль в `users/{uid}`:

```text
name, email, phone, createdAt, fcmToken, pushRequestedAt
```

Сервер реагирует на появление профиля или новый запрос push, отправляет сообщение через Firebase Admin SDK и записывает результат в `registrationPush/{uid}`. Статус `sent` означает принятие сообщения FCM; получение на устройстве подтверждается отдельно обработчиком приложения или уведомлением Android. При обновлении FCM-токена приложение сохраняет новый токен.

Кнопка «Повторить запрос push» позволяет повторно запросить разрешение и уведомление. Если разрешение запрещено в настройках Android, сначала включите его там.

## Основные файлы

| Файл | Назначение |
| --- | --- |
| `lib/main.dart` | Инициализация Firebase, старт приложения и фоновый обработчик |
| `lib/registration.page.dart` | Форма, валидация, ошибки и успешная регистрация |
| `lib/services/registration_service.dart` | Firebase Auth, запись профиля, обновление токена и статус отправки |
| `lib/services/push_service.dart` | Разрешения, FCM и показ уведомлений |
| `functions/local-worker.js` | Действующий сервер отправки на компьютере |
| `functions/send-registration-push.js` | Отправка через Firebase Admin SDK |
| `functions/index.js` | Альтернативный обработчик Cloud Functions |
| `database.rules.json` | Опубликованные правила доступа к базе |
| `scripts/verify-registration.cjs` | Проверка лабораторных записей без вывода токенов |
| `docs/evidence/` | Скриншоты фактической проверки |

Cloud Functions подготовлены как альтернативный вариант для размещения на сервере Google, но не развёрнуты: для этого требуется отдельно подключить Blaze. Перед таким развёртыванием остановите локальный сервер, чтобы не отправлять одинаковые сообщения дважды.
